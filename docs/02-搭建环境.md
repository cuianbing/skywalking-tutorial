# 第 2 篇 · 搭建 SkyWalking 环境

> 本篇目标是搭起一套能用的 SkyWalking 服务端（OAP + UI + BanyanDB 存储）。提供三条路线，**任选其一**即可：
>
> - **路线 A：Windows 本地直装** —— 学习/开发首选，解压即用，最直观；
> - **路线 B：Docker Compose** —— 一条命令拉起全套，适合有 Docker 习惯的读者；
> - **路线 C：Linux 服务器部署** —— 面向团队测试/生产环境的形态。
>
> 三条路线装出来的东西完全一样，完成后都请做一遍第五节的验证清单。

**版本约定**：OAP `10.4.0`（内置 UI）+ BanyanDB `0.10.x`。为什么选这套组合见 [README](/)。

---

## 一、先认清要装的东西

| 组件 | 是什么 | 进程形态 | 默认端口 |
| --- | --- | --- | --- |
| **OAP Server** | 服务端核心（接收探针数据、分析、告警、查询接口） | Java 进程 | 11800(gRPC) / 12800(HTTP) |
| **UI** | Web 界面 | Java 进程（内置在 OAP 发行包里，10.x） | 8080 |
| **BanyanDB** | 默认存储（自研观测数据库） | 独立二进制（Go 编写，很轻量） | 17912 / 17913 |

注意两点：

1. **10.x 的发行包同时包含 OAP、UI 和 Java Agent**（`agent/` 目录），解压一个包就够了；
2. **BanyanDB 是必须的**：从 10.2.0 起，H2 内存库已被永久移除，没有 BanyanDB（或 ES/MySQL）OAP 起不来。

资源要求：学习环境一台 2C4G 的机器（或本机 Windows/Mac）足够；OAP 默认 JVM 堆建议 1~2GB，BanyanDB 几百 MB 即可。

## 二、准备 JDK

OAP 是 Java 程序，运行它需要 **JDK 11 / 17 / 21 / 25**（**推荐 17**，最稳妥）。

```bash
# 检查版本（注意是 JDK 不是 JRE，且不能低于 11）
java -version
```

- Windows：从 [Adoptium](https://adoptium.net/) 下载 Temurin JDK 17 安装，并配置 `JAVA_HOME`；
- Linux（yum 系）：`yum install -y java-17-openjdk java-17-openjdk-devel`；
- Linux（apt 系）：`apt install -y openjdk-17-jdk`。

> Java Agent（探针）对业务应用的 JDK 要求更宽：JDK 8 ~ 25 都可以，与 OAP 的 JDK 版本无关。

## 三、下载发行包

| 文件 | 地址（写作时点已核实） |
| --- | --- |
| OAP 10.4.0 二进制包 | `https://archive.apache.org/dist/skywalking/10.4.0/apache-skywalking-apm-10.4.0-bin.tar.gz` |
| Java Agent 9.8.0（可选，包内自带） | `https://dlcdn.apache.org/skywalking/java-agent/9.8.0/apache-skywalking-java-agent-9.8.0.tgz` |
| 最新版本（11.x） | 一律从官方下载页 <https://skywalking.apache.org/downloads> 取 |

下载后校验一下完整性（可选但推荐）：

```bash
# 官方 sha512
curl -O https://archive.apache.org/dist/skywalking/10.4.0/apache-skywalking-apm-10.4.0-bin.tar.gz.sha512
sha512sum apache-skywalking-apm-10.4.0-bin.tar.gz   # 与 .sha512 文件内容比对
```

## 四、认识发行包目录结构

解压 `apache-skywalking-apm-10.4.0-bin.tar.gz` 后（Windows 10+ 自带 tar：`tar -xzf 文件名`，或用 7-Zip 右键解两次）：

```text
apache-skywalking-apm-bin/
├── bin/                    # 启动脚本（.sh / .bat）
│   ├── oapService.sh|.bat      # 只启动 OAP
│   ├── webappService.sh|.bat   # 只启动 UI
│   └── startup.sh|.bat         # 一键启动 OAP + UI ★常用
├── config/                 # OAP 配置
│   ├── application.yml         # 主配置（模块/存储/端口）
│   ├── bydb.yaml               # BanyanDB 连接与 TTL（10.2+ 独立出来）
│   ├── bydb-topn.yaml          # BanyanDB TopN 预聚合规则
│   ├── alarm-settings.yml      # 告警规则（第 4 篇讲）
│   └── log4j2.xml
├── oap-libs/               # OAP 依赖 jar
├── webapp/                 # UI 前端（booter jar + webapp.yml，UI 端口/后端地址在此改）
├── agent/                  # Java Agent ★第 3 篇主角
│   ├── skywalking-agent.jar
│   ├── config/agent.config     # 探针配置
│   ├── plugins/                # 已启用的插件（删掉 jar 即停用）
│   ├── optional-plugins/       # 可选插件（要手动拷进 plugins/）
│   └── logs/                   # 探针自身日志
└── logs/                   # OAP/UI 运行日志
```

好消息：**10.x 默认配置已经是"BanyanDB 存储 + 标准端口"，零修改即可启动**——前提是 BanyanDB 已经跑起来了（默认连 `127.0.0.1:17912`）。

## 五、路线 A：Windows 本地直装（推荐新手）

### A-1 启动 BanyanDB

Windows 上最省事的方式是用 **Docker Desktop** 跑 BanyanDB（容器只跑这一个小组件，OAP/UI 照旧原生跑）：

```bash
docker run -d --name banyandb ^
  -p 17912:17912 -p 17913:17913 ^
  apache/skywalking-banyandb:0.10.0 standalone
```

> - `standalone` 是单机模式，学习/中小规模够用；
> - tag 说明：**OAP 10.4.0 要求 BanyanDB 的 API 版本为 0.10**，即 0.10.x 系列小版本均可（写作时点以 0.10.0 为例）。**别用 0.11.x**，那是给 OAP 11.x 用的，版本不配对 OAP 会直接启动失败并打印 `Incompatible BanyanDB server API version`；
> - 没装 Docker Desktop？也可以去 [BanyanDB 的 GitHub Releases](https://github.com/apache/skywalking-banyandb/releases) 下载服务器二进制（Windows/Linux/macOS 包以 Release 页实际提供为准）解压运行 `banyand standalone`，效果相同。

### A-2 启动 OAP + UI

```bash
cd /d D:\skywalking\apache-skywalking-apm-bin\bin
startup.bat
```

`startup.bat` 会弹出两个命令行窗口：一个 OAP、一个 UI。验证：

- 打开 `logs\skywalking-oap-server.log`，能看到 `The key booting parameters of Apache SkyWalking OAP are listed as following.` 且没有持续刷 ERROR，即启动成功；
- 浏览器访问 **http://localhost:8080**，能看到 SkyWalking 界面（此时没有数据，页面大都是空的，属正常——数据要等第 3 篇接入应用后才有）。

### A-3 停止与重置

- 停止：直接关闭那两个命令行窗口（或 Ctrl+C）；
- 想清空数据：停掉 BanyanDB 容器后 `docker rm -f banyandb` 删除重建即可。

## 六、路线 B：Docker Compose 一键全套

适合熟悉 Docker 的读者。新建 `docker-compose.yml`：

```yaml
services:
  banyandb:
    image: apache/skywalking-banyandb:0.10.0   # OAP 10.x 配 0.10.x；别混用 0.11
    command: standalone
    ports:
      - "17912:17912"
      - "17913:17913"
    volumes:
      - banyandb-data:/data

  oap:
    image: apache/skywalking-oap-server:10.4.0
    environment:
      SW_STORAGE: banyandb
      SW_STORAGE_BANYANDB_TARGETS: banyandb:17912   # 指向上面容器名
    ports:
      - "11800:11800"    # 探针上报
      - "12800:12800"    # UI 查询
    depends_on:
      - banyandb
    restart: unless-stopped

  ui:
    image: apache/skywalking-ui:10.4.0
    environment:
      SW_OAP_ADDRESS: http://oap:12800
    ports:
      - "8080:8080"
    depends_on:
      - oap
    restart: unless-stopped

volumes:
  banyandb-data:
```

启动与验证：

```bash
docker compose up -d
docker compose ps                 # 三个容器应全部 Up
# 浏览器访问 http://localhost:8080
```

> **小坑**：OAP 启动时要连 BanyanDB 初始化 schema。如果 OAP 容器因连不上 BanyanDB 反复报错退出，等 BanyanDB 就绪后 `docker compose restart oap` 即可，之后自动恢复。

镜像 tag 说明：`apache/skywalking-oap-server`、`apache/skywalking-ui`、`apache/skywalking-banyandb` 三个镜像在 [Docker Hub](https://hub.docker.com/u/apache) 均有对应版本的 tag，以实际页面为准。

## 七、路线 C：Linux 服务器部署（测试/生产形态）

### C-1 规划目录与下载

```bash
mkdir -p /opt/skywalking && cd /opt/skywalking
wget https://archive.apache.org/dist/skywalking/10.4.0/apache-skywalking-apm-10.4.0-bin.tar.gz
tar -xzf apache-skywalking-apm-10.4.0-bin.tar.gz          # 解出 apache-skywalking-apm-bin/
```

BanyanDB 同样两种装法：Docker（`docker run -d -p 17912:17912 -p 17913:17913 apache/skywalking-banyandb:0.10.0 standalone`）或下载 GitHub Release 的 linux-amd64 二进制跑 `banyand standalone`。生产建议为 BanyanDB 单独规划数据盘。

### C-2 先跑通（手动验证）

```bash
cd /opt/skywalking/apache-skywalking-apm-bin/bin
./startup.sh            # 启动 OAP + UI
tail -f ../logs/skywalking-oap-server.log
# 看到 booting parameters 列表、无 ERROR 即成功；浏览器访问 http://服务器IP:8080
```

如需调整 OAP 堆内存，编辑 `bin/oapService.sh` 中的 `JAVA_OPTS`（如 `-Xms1g -Xmx2g`）。

### C-3 注册 systemd 服务（开机自启）

```ini
# /etc/systemd/system/skywalking-oap.service
[Unit]
Description=SkyWalking OAP Server
After=network.target

[Service]
Type=simple
User=app
WorkingDirectory=/opt/skywalking/apache-skywalking-apm-bin
ExecStart=/opt/skywalking/apache-skywalking-apm-bin/bin/oapService.sh
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```ini
# /etc/systemd/system/skywalking-ui.service
[Unit]
Description=SkyWalking UI
After=skywalking-oap.service

[Service]
Type=simple
User=app
WorkingDirectory=/opt/skywalking/apache-skywalking-apm-bin
ExecStart=/opt/skywalking/apache-skywalking-apm-bin/bin/webappService.sh
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now skywalking-oap skywalking-ui
systemctl status skywalking-oap
```

> 两个业务账号建议单独建（如上面的 `app` 用户），不要用 root 跑。

### C-4 防火墙放行

```bash
# firewalld 示例
firewall-cmd --permanent --add-port=8080/tcp --add-port=11800/tcp --add-port=12800/tcp
firewall-cmd --reload
```

三个端口的安全边界务必想清楚：

| 端口 | 给谁用 | 是否该暴露公网 |
| --- | --- | --- |
| 8080（UI） | 团队成员浏览器 | 不该，建议 Nginx 反代 + 鉴权 |
| 11800 | **业务机器上的探针** | 不该公网暴露；放行内网业务机器 IP |
| 12800 | UI 查询 | 不该公网暴露 |

## 九、11.x 版本变化速览

如果你所在团队用的是 SkyWalking 11.x（或将来升级），以下变化会影响"搭建环境"的每一个环节，先混个眼熟：

| 变化 | 10.x（本教程） | 11.x |
| --- | --- | --- |
| Web UI | 发行包内置（`bin/startup` 一键起，端口 8080） | **不再内置**。UI 为独立项目 Horizon UI，用镜像 `apache/skywalking-ui` 部署，与 OAP 版本号不再一一对应，升级节奏各自独立 |
| UI 依赖端口 | UI → OAP 12800 | UI → OAP 12800（查询不变）+ OAP 需暴露 **17128**（UI 管理/模板接口走 admin-server） |
| 发行包 | 含 `webapp/` 目录与 `webappService` 脚本 | 无 `webapp/` 目录、无 `webappService` 脚本 |
| admin-server | 无 | 新增（HTTP 17128 / 内部 gRPC 17129），承载状态检查、UI 管理、规则热更新、调试器等，**默认无鉴权，必须网关/IP 白名单保护，严禁暴露公网** |
| BanyanDB | 0.10.x（API 0.10） | 0.11.x（API 0.11） |
| 其他 | — | MAL/LAL 规则运行时热更新、Elasticsearch 9 支持等 |

升级提示：OAP 11.x + BanyanDB 0.11.x + `apache/skywalking-ui`（latest 或 horizon-xxx tag）三件套即可复刻本篇的 Compose 结构，把 banyandb 镜像换成 0.11.x、UI 换成 `apache/skywalking-ui` 并暴露 OAP 的 17128 即可。

## 十、常见问题（FAQ）

**Q1：OAP 启动立刻退出 / 日志报 `Incompatible BanyanDB server API version`**
BanyanDB 版本与 OAP 不配对。OAP 10.4.x ↔ BanyanDB 0.10.x；OAP 11.x ↔ BanyanDB 0.11.x。

**Q2：OAP 日志持续报连接 17912 失败**
BanyanDB 没起来、地址不通或防火墙拦截。先确认 `telnet 127.0.0.1 17912`（或对应主机）能通。

**Q3：8080 端口被占用**
编辑 `webapp/webapp.yml` 中的 `serverPort`（UI 端口）后重启 UI；或改用 Docker 方式映射到别的宿主端口。

**Q4：11800/12800 被占用**
编辑 `config/application.yml` 中 `core` 下的 gRPC/rest 端口。注意改完之后探针侧 `collector.backend_service` 也要同步改。

**Q5：Windows 下双击 startup.bat 窗口一闪而过**
多半是没装 JDK 或 `JAVA_HOME` 没配。先在 CMD 里 `java -version` 确认；再看 `logs/` 下是否有错误日志。

**Q6：能用 MySQL/Elasticsearch 做存储吗？**
可以。`config/application.yml` 里 `storage.selector` 可选 `banyandb`（默认）/ `elasticsearch` / `mysql` 等。ES 适合超大规模（也最吃资源）；MySQL/PG 适合中小规模且链路/日志采样率低的场景。初学不建议折腾，默认 BanyanDB 即可。
